# Adult site blocklist

`extension/rules/adult.json` is the static declarativeNetRequest ruleset behind
the "Block adult sites" feature. It is generated by
`scripts/build-adult-list.mjs` and committed, so every build of the extension
ships the same reviewable list. Nothing is downloaded at runtime: the extension
makes no network requests of its own, the list is read by Chrome from the
extension package when the ruleset is enabled.

Tranco is used only as a popularity filter at build time. No rank data and no
Tranco entry that is not also on one of the two blocklists ends up in the
generated file, so the extension does not redistribute the Tranco list.

Both blocklists are hosts files with several hundred thousand entries. They are
far too large to ship, and they contain a noticeable number of mistakes
(see "Known problems with the sources" below), which is why the build filters
and reviews them rather than concatenating them.

## How the list is built

1. Download the two blocklists and the Tranco archive. The zip is unpacked
   with a small built-in reader (`node:zlib` inflateRawSync on the single
   entry), falling back to the `unzip` command. If Tranco cannot be fetched
   the script exits with status 1 rather than producing an unfiltered list.
2. Parse the hosts files: lowercase, trim, drop comments, `localhost` and
   friends, IP addresses and anything that is not a valid domain name.
   Unicode names are converted to punycode through `new URL()`.
3. Popularity filter: a domain is kept when it is in the Tranco list. A domain
   whose registrable parent (last two labels, or three under `co`, `com`,
   `net`, `org`, `gov`, `edu`, `ac` with a two-letter TLD) is in Tranco is
   kept as well, unless the parent is on the allow list or looks like a
   hosting platform (a parent that is not blocked itself but has 20 or more
   blocked subdomains, such as `tumblr.com` with 161,825 entries or
   `blogspot.com` with 70,285). Entries kept only through their parent sort
   after all exact matches, so they only fill the list when there is room.
   In the current build none of them made it in.
4. Remove every domain on the script's allow list, and everything under such
   a domain.
5. Add every domain from `scripts/adult-core.txt`, a hand-curated list of
   well-known tube, cam, creator, hookup, escort, image and comic sites. Core
   domains are always included, whether or not Tranco knows them.
6. Prune: if a domain's parent is also in the set, drop the subdomain.
   `requestDomains` matches subdomains on its own.
7. Cap at 15,000 domains: the core list first, then the remaining candidates
   by Tranco rank, best ranked first.
8. Sort and write `adult.json`:
   - rule 1 redirects main-frame requests for every listed domain to the
     block page, appending the original URL as `?u=`;
   - rules 2 to 6 are hostname keyword rules, at most six keywords per
     RE2 regex: `porn`, `xxx`, `xvideos`, `xnxx`, `xhamster`, `hentai`,
     `redtube`, `brazzers`, `chaturbate`, `stripchat`, `livejasmin`,
     `bongacams`, `onlyfans`, `fansly`, `rule34`, `spankbang`, `camsoda`,
     `myfreecams`, `erome`, `motherless`, `fapello`, `thothub`, `tnaflix`,
     `xmoviesforyou`, `beeg`, `cam4`, `jerkmate`. `pornhub`, `youporn`,
     `eporner`, `hqporner` and `nhentai` are not listed separately because
     `porn` and `hentai` already match them. `erome` requires a word boundary
     in front (otherwise `aeromexico.com` and `jeromes.com` match), `beeg` and
     `cam4` must be a whole label (`beegees.com`, `beegfs.io`, `cam4lab.dev`).
     Generic words such as sex, nude, adult, girls, teen or cam are not used;
     `sussex.ac.uk` and `adulteducation.org` would match.
   - rule 7 is an allow rule with a higher priority for benign hostnames
     that a keyword still matches, found by running the keywords over the
     Tranco list: the XXXLutz furniture group, `mixxx.org`, `pornic.fr`
     (a town in France), `odpornosc.org.pl` (Polish for immunity) and a few
     more.

The domain rule packs eight domains per line so that the file stays small.

## Regenerating

```
npm run blocklist
npm test
```

The script needs Node 22 and network access. Tranco publishes a new list every
day, so a rebuild usually changes the tail of the list. Review the diff for
mainstream domains before committing, and add them to the allow list in the
script when found.

## Known problems with the sources

Both blocklists are broad and include many sites that are not adult sites:
user-content platforms (Tumblr, Blogspot, Xiaohongshu, 4chan), mainstream
media (Cosmopolitan, Refinery29, Ekstra Bladet, ET Online, VH1), tools and
shops (CamScanner, Fasthosts, 101domain, HMV Japan, Yes24, XXXLutz), general
dating apps (Tinder, Badoo, Match, OkCupid, Grindr) and AI chat products
(character.ai). The allow list inside `scripts/build-adult-list.mjs` removes
the ones found while reviewing the top of the ranked output. Entries further
down the list were not reviewed one by one, so more mistakes are certain to
exist there. Hookup and escort sites are deliberately kept.

## False positives at runtime

Anything the bundled list gets wrong can be fixed by the user on the options
page: "Blocked sites" has an allow list, applied as dynamic allow rules with a
higher priority than the bundled rules, and a block list for additions. Both
are stored in `blocker.allowedDomains` and `blocker.blockedDomains`. Changing
the allow list is only possible while the filter is off, so it cannot be used
to bypass the countdown.

Fixes that apply to everyone (a mainstream domain in the sources, a keyword
hitting an ordinary word) belong in the script's allow list or keyword
exceptions, followed by a rebuild.
